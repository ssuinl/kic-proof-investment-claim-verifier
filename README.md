# PROOF — 투자 근거 검증 서비스 (기획)

KIC AI Agent Competition 2026 (한국투자공사) · 개인 참가 · 예선 기획서 · 2026.11

## 기획 배경
해외 상장기업 리서치 메모에서는 다음 같은 문제를 사람이 하나씩 가려내야 합니다.
- 수치·계산 오류: 원문 수치를 잘못 인용하거나 증가율·비율을 잘못 계산함
- 정보 공개 시점 오류: 메모 기준일 이후에 공개된 자료를 근거로 씀
- 사실과 해석의 혼합: "재무 위험이 완전히 해소되었다" 같은 판단이 사실처럼 단정됨
- 근거 추적의 어려움: 어떤 공시·회계기간·항목으로 판단했는지 재현하기 어려움

기존 투자 메모의 주장을 나누어 SEC 공시와 비교하는 Agent를 제안했습니다.

## 활용 예정 데이터
| 데이터 | 활용 |
|---|---|
| SEC Submissions API | 공시 종류·제출일·식별자 → 공시 탐색, 시점 판정 |
| SEC Company Facts API (XBRL) | 정형 재무 수치·기간·단위 → 정량 주장 검증 |
| Form 10-K / 8-K (Exhibit 99.1) | 연차보고서·실적발표 원문 → 수치 재확인, 기준일 이전 대체 증거 |
| 평가용 투자 메모 | 공시 기반 정상 주장 + 오류 주입 → 성능 평가 (기업 단위 분리) |

## 서비스 설계
### Agent 흐름
`Parse(주장 분해) → Plan(지표·증거 계획) → Act(공시 조회·계산) → Observe(적합성 확인) → Replan(대체 증거 탐색) → Validate(판정 조건 검사) → Report`

### 검증 기준
1. 역방향 검증: 새 투자 의견을 만들지 않고, 사람이 쓴 주장을 증거와 대조합니다.
2. 기준일 시점 검증: 제출일이 메모 기준일 이전인 증거만 채택합니다. 회계기간은 `fy`·`fp` 필드가 아니라 값의 start·end 날짜로 판단합니다.
3. 측정 가능한 보류: 근거가 부족하면 판정을 보류합니다. 잘못된 일치 판정률(FVR)은 Coverage와 함께 보고합니다.

### 역할 분리
| 담당 | 하는 일 |
|---|---|
| LLM | 주장 분해, 지표 매핑, 도구 선택, 재계획 |
| Python 규칙 | 계산, 수치 비교, 판정 (LLM이 낸 수치는 판정 근거로 쓰지 않음) |

Tool 목록: `get_filings`, `get_financial_facts`, `calculate_metric`, `check_temporal_validity`, `find_alternative_filing`, `validate_evidence`, `generate_verification_report`

증거 판정 4단계: 일치 / 불일치 / 근거 부족 / 범위 제외

### 검증 사례 (Starbucks FY2025, 수동 검증)
가상 메모: 작성 기준일 2025-10-31, 주장은 "FY2025 유동자산 15% 증가, 현금 보유 증가, 재무 위험 완전 해소"

| 단계 | 처리 | 결과 |
|---|---|---|
| 시점 확인 | 10-K는 11/14에 제출돼 기준일 이후 | 10-K 배제 |
| 재계획 | 10/29에 제출된 8-K Ex.99.1의 재무상태표 확보 | 대체 증거 |
| 수치 검증 | 유동자산 6,847.4 → 7,382.3 (US$ M), 실제 +7.81% | 불일치 |
| 지표 재확인 | 현금성자산 −2.02%, 단기투자 포함 −2.15% | 불일치 |
| 해석 분리 | "위험 해소"는 해석형 주장 → 관련 수치(유동부채 +12.57%)만 제시 | 사람 검토 |
